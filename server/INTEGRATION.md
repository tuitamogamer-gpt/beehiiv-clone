# Backend integration contract

Root owns core Store, error/helpers, queue runner, API composition, dependency manifests, Vercel entrypoint, migrations, aggregate workspace API. Agents own only their assigned module/test directories.

- Use TypeScript ESM imports with `.js` suffix in server modules (tsx resolves TS; Vercel bundles).
- `server/contracts.ts` defines Services, Store, Api, Ctx, Stored, Principal.
- Each module exports `registerX(app: Api, services: Services): void` and may export domain helpers. App is Hono with basePath `/api` so routes register `/subscribers` etc.
- `store` is tenant scoped JSON records with optimistic versioning, cursor pagination, SQL parameterization. `transaction(async tx => { await tx.lock(key); ... })` ensures atomicity. SQLite dev uses exclusive transaction; PostgreSQL advisory xact lock.
- `get/list/insert/update/remove` require tenant+kind. Never use client tenant or user IDs for authorization. `insert` optional explicit ID is unique per tenant+kind (db unique key). Throws `ApiError(409, 'conflict', ...)` on duplicate or stale version.
- Helpers in `server/core/http.ts`: `ApiError(status, code, message)`, `jsonBody(c, schema)` (zod), `principal(c)` throws401; `requireRole(c, ...roles)` throws403; `requireScope(c,scope)` rejects API keys without scope; `id()` uuid, `now()` ISO, `hash(value)` sha256hex, `randomToken(bytes=32)` base64url, `audit(services, principal, action, details)`.
- Config in `server/core/config.ts`: `config` { production:boolean, appUrl:string, databaseUrl?:string, sqlitePath:string, sessionSecret?:string, cronSecret?:string, resendApiKey?:string, resendWebhookSecret?:string, emailFrom?:string, stripeSecretKey?:string, stripeWebhookSecret?:string, turnstileSecretKey?:string, openaiApiKey?:string, blobToken?:string, bootstrapToken?:string }. No logging secrets.
- Outbound JSON/network helpers in `server/core/network.ts`: `safeFetch(url,options)` rejects nonHTTPS, private IP/DNS, credentials, blocks redirect following, enforces 15s timeout. Use for user-configured external webhook URLs and content ingestion. Provider fixed known domains can use normal fetch with timeout.
- Auth module exports `authenticate(services): MiddlewareHandler<{Variables:Variables}>`; attaches principal if valid session/Bearer key, leaves unset on public routes. `principal(c)` guards protected endpoints. `registerAuth` handles auth routes. System records use tenantId `__system__` (users, sessions, login tokens), only auth should access system records. Publication/workspace `tenant` records also stored there to route public slugs.
- Auth server sessions from HttpOnly cookie `bh_session`; Bearer API key token hash stored in system `api_key`, data tenantId/userId/role/scopes. Both recheck current membership (system `membership` records data {userId, tenantId, role, email,name}) on every call. Common principal may have scope.
- All app entities kinds singular: `post`, `subscriber`, `automation`, `product`, `publication`, `suppression`, `template`, `segment`, `job`, `event`, `webhook_endpoint`, `webhook_delivery`, `comment`, `poll`, `survey`, `order`, `subscription`, `community_channel`, `community_post`, `podcast_show`, `podcast_episode`, `website_page`, `redirect`, `media`. Record id plus data is returned as `{id,...data,version}` when helpful. Source and actual stats are never fabricated.
- Publication data keeps frontend shape {name,description,domain,sender,accent}, plus public `slug`, verifiedDomain and subscription settings. One tenant=one publication; workspace records can group tenants.
- Subscriber data keeps frontend {name,email,status:'Active'|'Pending'|'Unsubscribed',tier:'Free'|'Premium',source,joined,openRate,tags}, plus customFields, token hashes/consent. Never send to Pending/Unsubscribed.
- Post data keeps frontend {title,subtitle,content,status:'Draft'|'Scheduled'|'Published',date,audience,opens,clicks,image,subjectB}; scheduling through dedicated send endpoint; generic CRUD cannot mark Published, must require email provider config/valid domain before real sends.
- Automation data extends frontend steps string[] with structured nodes. Until nodes configured no real enrollment execution. Actual jobs register via Services.registerJob and share durable queue.
- Provider dependencies planned: hono, @hono/node-server, pg, zod, sanitize-html, stripe, svix, @vercel/blob, tsx, @types/node, @types/pg, @types/sanitize-html. Root installs. Node24 sqlite builtin for tests/dev only; production requires DATABASE_URL and fails503 if absent. No production SQLite fallback.
- Module tests use node:test via `tsx --test server/tests/*.test.ts`; root exposes `createSqliteStore(':memory:')` from core/store.ts and `createServices(store)` from core/services.ts. `createApp(services)` composes all modules. Config env values can be set before dynamic import; test-only transports must be injected, never available from production requests.
